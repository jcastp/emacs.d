#+author: Javier Castilla

This manual covers what this configuration adds on top of stock Emacs in the
*personal* environment (=WORKING= unset or =HOME=). Work-only features are left
out.

Each chapter first explains how a system works day to day, then gives its keys.
[[*Appendix A — Key reference][Appendix A]] collects every custom binding in one place.

The source of truth is always =config/*.org=. When this manual and the config
disagree, the config wins. The module that owns each feature is named in
brackets, e.g. [40-org], so you know where to look.

* Orientation

** Conventions used here
- =C-q= is the *personal prefix*. Press it and wait: which-key lists
  everything under it. =C-q= no longer quotes characters
  (=quoted-insert=); use =M-x quoted-insert= when you need it.
- =C-c <letter>= bindings are the usual user-reserved space. Most org, roam and
  agenda commands live there.
- Keys written as =ññ= or =jj= are *key chords*: two keys pressed together (or
  the same key twice) quickly.
- The Spanish keyboard layout is assumed: =ñ= and =¡¿= appear in bindings.

** What happens at startup
/[init.el, 10-ui, 15-theme, 30-navigation, 80-apps]/
1. The frame opens maximised, with no menu, tool or scroll bars.
2. A dark theme is applied (the first of the dark rotation, see
   [[*Themes, fonts and org styles][Themes]]) and the =hack= font preset is set.
3. The *dashboard* shows the banner, 5 recent files, 5 bookmarks, 5 projects
   and 5 agenda items.
4. The org-roam database starts syncing about a second after you stop typing,
   so that work stays off the startup path.
5. If the encrypted directory (=~/Nextcloud_claro/gocryptfs_claro=) is
   mounted, the journal and Mastodon become available. If not, you get the
   message /Encrypted directory not mounted/ and those two features are
   skipped.

* Everyday editing

** Editing behaviour
/[00-core]/
- *Fill toggle*: =M-q= fills the paragraph (or the region). Press it again
  straight away to unfill it; consecutive presses keep alternating. After any
  other command, the next =M-q= fills again.
- *Kill a word*: =C-w= with no active region kills the word at point.
- *Typing replaces a selection* (=delete-selection-mode=).
- *Paragraph movement*: =M-n= / =M-p= go forward and back by paragraph.
- *Electric pairs*: =(=, ="= and friends close themselves, and so do =¡…!= and
  =¿…?=. =<= is deliberately *not* paired, so tempel's =<= trigger works.
- *Visual undo*: =C-z= opens =vundo=, an undo tree you can walk through.
- *Smarter =C-g=*: it closes a minibuffer even when focus is elsewhere, and
  closes the =*Completions*= window.
- *Diff before saving*: when =C-x s= or =C-x C-c= asks about unsaved buffers,
  answer =d= to see a diff of what would be saved.
- *Abbrevs* are on in text and code buffers, and are saved silently to
  =abbrev_defs= in the data directory.
- Short answers (=y= / =n=) everywhere, and quitting Emacs asks first.
- Files reload automatically when they change on disk. Your place in each file
  is remembered.
- =C-c r r= reloads the whole configuration.

** Spelling and language
/[00-core, 20-completion]/
Spelling is *jinx*, which checks as you type.

| Key   | Command                                |
|-------+----------------------------------------|
| =M-$=   | correct the misspelling at point       |
| =C-M-$= | change this buffer's spelling language |

The default language is *English only*. A Spanish file says so with
=#+language: es= near the top (or a file-local =jinx-languages=). One language
at a time is deliberate: loading both would silently accept every en/es false
friend (/actual/, /once/, /sin/ ...).

In-buffer completion follows the same language: the dictionary words offered
in the completion popup come from that language's hunspell list. So =C-M-$=
switches both the spellchecker and the completion words at once. Words from
your open buffers are offered whatever their language.

** Completion
/[20-completion]/
*Minibuffer*: vertico shows candidates vertically, sorted by prescient (it
learns what you pick). orderless lets you type space-separated fragments in any
order. marginalia adds annotations, with icons.

*In the buffer*: corfu pops up after 3 characters (0.4 s). It offers words from
open buffers plus dictionary words, and closes as soon as you type a space.
=TAB= indents first and completes when there is nothing left to indent.

*Embark*: =C-.= on anything (a candidate, a file name, a URL) opens a menu of
actions for it. =C-h B= lists the current bindings through embark.

*Consult commands*:

* Themes, fonts and org styles

** Themes
/[15-theme]/
There are two rotations:
- dark: =ef-deuteranopia-dark=, =modus-vivendi-tinted=
- light: =leuven=, =ef-deuteranopia-light=, =modus-operandi=

=C-c 0= flips between dark and light. Each flip takes the /next/ theme of that
rotation, so pressing it repeatedly walks through all of them. =C-q t t= picks
any theme by name.

Every theme change also recomputes the current-line colour and the org faces
(below), so the org look stays consistent across themes.

** Font presets
/[15-theme]/
=C-q t f= switches fontaine preset:
| Preset                | Use                                                  |
|-----------------------+------------------------------------------------------|
| =hack=                  | default at startup; Hack everywhere                  |
| =regular=               | Aporetic Sans (prose) + Aporetic Sans Mono (code)    |
| =regular-aporetic-mono= | Aporetic Sans Mono everywhere                        |
| =writing=               | ETBembo 150, extra line spacing                      |
| =writing-big=           | ETBembo 180 (org-scribe's distraction-free mode)     |
| =editing=               | Gentium prose, mono code (org-scribe's editing mode) |

Prose buffers (text and org) use the variable-pitch font. Code blocks, tables,
tags, drawers and comments stay fixed-pitch. =M-+= / =M--= scale the text.

** Org heading styles
/[17-org-style]/
Org headings are drawn from the active theme's own colours in one of three
looks:
| Style | Name              | Headings                                 | Rules                          |
|-------+-------------------+------------------------------------------+--------------------------------|
| =a=     | typographic       | one colour, size and weight only         | none                           |
| =b=     | restrained accent | theme accent on H1/H2, body colour below | none                           |
| =c=     | structured        | one colour                               | hairline over H1/H2 and blocks |

Style =c= is the default.

| Key     | Does                                |
|---------+-------------------------------------|
| =C-q s s= | choose a style                      |
| =C-q s n= | next style (a → b → c)              |
| =C-q s ?= | describe the active style and theme |

Drawers, =#+keywords=, properties and tags are always smaller, fixed-pitch and
dimmed: they are machinery, not content. Heading levels 5–8 fade toward the
background instead of changing colour. The *poet* themes (org-scribe's
writing theme) keep their own heading colour.

** Other visual details
/[10-ui, 17-org-style]/
- Long lines wrap visually everywhere. =C-q t v= toggles visual-fill-column
  (110 characters, centred).
- Line numbers are on everywhere (except in writing focus mode).
- The modeline is doom-modeline, with time and date (and battery on laptops).
- org-modern draws keywords, tags, timestamps, tables and block names more
  cleanly. =#+title= appears as =‣title=.
- org-appear shows hidden emphasis markers, link targets and entities
  (=*bold*=, =\alpha=) when the cursor reaches them, after 0.2 s, and hides them
  again when you leave.

* Org mode

** Defaults worth knowing
/[40-org]/
- Every org buffer is indented (=org-indent-mode=): text sits under its heading
  and only the last star of each heading shows.
- New headings get a blank line before them and go /after/ the current subtree.
- =C-a= / =C-e= on a heading skip the stars, keyword and tags.
- Editing inside a folded region is refused only when it would be blind (=smart=).
- Folded headings end in =…=.
- State-change notes go into a =:LOGBOOK:= drawer. Rescheduling and changing a
  deadline are *not* logged. Finishing a task records a =CLOSED:= timestamp,
  which the weekly review needs.
- Inline images show at startup, up to 800 px wide.
- Babel blocks run without asking for confirmation.

* Agenda and task management

** The files
/[45-agenda]/
The agenda reads =~/Nextcloud/agenda/tasks.org=, =someday.org= and =books.org=.
=tasks.org= is organized as /Inbox/, /Tasks/, /Writing/ and /Calendar/.

The flow the configuration is built for:
1. *Capture* anything into the /Inbox/ with =C-c c t=.
2. *Refile* it (=C-c C-w=) into /Tasks/, /Writing/, a project, =someday.org= or
   =referencias.org=.
3. *Tag* it with an area and, where it helps, a context and an energy level.
4. *Review* it through the views below.

** Look
/[45-agenda]/
- The default span is 14 days starting on Monday.
- A time grid runs from 8:00 to 20:00, with a =⭠ now= marker.
- Categories get SVG icons from =~/Nextcloud/config/icons/= (calendar, tasks,
  projects, financial, birthdays, revision, habits, care).
- DONE items are hidden from scheduled, deadline and timestamp entries.
- Habits (=org-habit=) are enabled: give a task a =STYLE: habit= property and a
  repeater.

** The agenda views
/[46-agenda-personal]/
=C-c a= opens the dispatcher. =C-q d= goes straight to /Daily/.

Each view is designed to answer one question at a set time:
| Key | View               | When                     | Question                                       |
|-----+--------------------+--------------------------+------------------------------------------------|
| =d=   | Daily              | every morning            | what needs my attention today?                 |
| =w=   | Week horizon       | Sunday evening / Monday  | what is coming up this week?                   |
| =R=   | Weekly review      | Friday / weekend         | how did my week go?                            |
| =ca=  | Areas of life      | monthly                  | how are my life areas doing?                   |
| =cw=  | Writing pipeline   | before a writing session | what writing needs attention?                  |
| =cb=  | Books              | anytime                  | what am I reading, what is next?               |
| =cs=  | Someday and goals  | weekly / monthly         | what is in my someday list?                    |
| =ce=  | Context and energy | a free slot              | what can I do, given where I am and my energy? |

What each view shows, block by block:
- *Daily*: today's agenda (deadlines warn 3 days ahead) · ONGOING ·
  priority-A TODOs · WAITING.
- *Week horizon*: deadlines for the next 2 weeks · ONGOING carry-over ·
  priority A · priority B · WAITING.
- *Weekly review*: what was completed in the last 7 days (DONE and FINISHED) ·
  unfinished health · unfinished financial · WAITING /chase or park?/ ·
  unscheduled TODOs /needs a home/.
- *Areas of life*: personal · health · financial · anything with /no/ area tag.
- *Writing pipeline* (=writing= tag): TOWRITE · TOREVIEW · REDO ·
  RESTRUCTURE · the blog queue · the last 10 FINISHED.
- *Books* (=books= tag): READING · ONHOLD · TOREAD · the last 20 READ, newest
  first by =DATE_FINISHED=.
- *Someday and goals*: =objetivos= · someday by area · other someday.
- *Context and energy*: high energy + @computer · @home · @penpaper ·
  @errands · @online · calls · low energy /quick wins/.

All views except /Someday/ exclude =someday= items. In the plain agenda
(=C-c a a=), org-super-agenda groups entries into Overdue, Today, Deadline this
week, In progress, Priority A, Waiting, Health, Financial, Personal, Writing,
Reading and Someday. Entries that match none of these appear at the end under
/Other items/, so nothing scheduled or due is hidden. The grouping applies to
this view only; every other agenda view is plain org.

** The reading list
/[80-apps, 46-agenda-personal]/
1. =C-c c b= captures a book into =books.org= as =TOREAD=, with =:AUTHOR:=,
   =:GENRE:=, =:FORMAT:=, =:PAGES:= and =:DATE_ADDED:= filled in. =:DATE_STARTED:=,

pages, dates and rating.

** The =roamtag= tag
Whenever a roam note is opened or saved, it is checked for live TODOs (not
DONE). If it has one, =roamtag= is added to its =#+filetags=; if not, the tag is
removed. You never set it by hand. It is what =C-c n T= picks from.

At home, roam TODOs are deliberately *not* merged into the main agenda. Use

** org-scribe in this configuration
/[60-writing]/
org-scribe is your writing toolkit. It is loaded from
=~/Nextcloud/escritura/software/org-scribe= if that directory exists, otherwise
from Codeberg (=development= branch). It is active in every org buffer.

How this config sets it up:
| Mode                     | Theme                | Font preset | Width |
|--------------------------+----------------------+-------------+-------|
| normal                   | =modus-vivendi-tinted= | =hack=        |    90 |
| distraction-free / focus | =poet=                 | =writing-big= |    75 |
| editing                  | =leuven=               | =editing=     |    90 |

The editing mode gives the outline 25 % on the left, *notes* 25 % on the right
and the manuscript 50 % in the centre. Automatic word counting on save is
*off*, because it is too slow on big files, so run =C-q w w= (hydra =a=) at the
end of a session.

The hydra (=F8 F8=) groups everything into columns:
- *Insert*: =s= scene, =c= chapter, =o= open project file.
- *Workspace*: =m= write, =f= focus, =e= edit, =v= navigate (treemacs + outline),
  =0= back to normal.
- *Tag scene*: =p= PoV, =h= characters, =l= locations, =g= plot threads, =j= jump to
  the PoV character.
- *Tools*: =w= count, =a= update all counts, =d= dictionary (RAE), =y= synonyms,
  =x= thesaurus.
- *Search*: =1= by PoV, =2= character, =3= plot, =4= location, =5= TODOs, =6= edit
  markers.

For everything else (creating novel and short-story projects, entity capture,
timelines, compilation, the planner) see org-scribe's own manual:

- [[file:~/Nextcloud/escritura/software/org-scribe/manual/getting-started-00-index.org][Getting started (18 lessons)]]
- [[file:~/Nextcloud/escritura/software/org-scribe/manual/getting-started-13-daily-workflow.org][Daily workflow]]
  and [[file:~/Nextcloud/escritura/software/org-scribe/manual/getting-started-14-revision-workflow.org][revision workflow]]

* Export and publishing

** Exporting
/[55-org-export]/
=C-c C-e= opens the export dispatcher. Available backends: HTML, Markdown,
Org, LaTeX/PDF, Beamer, EPUB, Pandoc (every format pandoc supports) and Hugo.

- A heading tagged =:ignore:= is dropped from the export but *its content is
  kept*. This is how chapter and scene headings disappear from a manuscript.
- A heading tagged =:noexport:= is dropped with its content.
- Smart quotes are on, HTML exports have no "validate" link, and code in LaTeX
  uses =minted=.
- The =<export= tempel template inserts a complete settings heading.

** LaTeX classes
/[55-org-export]/
Set with =#+LATEX_CLASS:=:
| Class                | What                                                            |
|----------------------+-----------------------------------------------------------------|
| =memoir=               | A4 book, parts and chapters, Spanish, final                     |
| =memoir_draft=         | the same, draft mode                                            |
| =memoir_chapter=       | chapters as the top level (no parts), final                     |
| =memoir_chapter_draft= | chapters as the top level, draft                                |
| =reporting=            | memoir with plain page style, Spanish                           |
| =ews=                  | the Emacs Writing Studio book layout (EB Garamond, 9.25×7.5 in) |

The Spanish classes define three commands you can use in =#+LATEX:= lines or
export snippets: =\fin= (a scene break), =\edit{…}= (an inline todo note) and
=\adendo{…}= (a small margin note). PDFs are built with pdflatex + bibtex, and
the temporary files are cleaned afterwards.
