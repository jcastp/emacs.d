#+author: Javier Castilla

This manual covers what this configuration adds on top of stock Emacs in the
*personal* environment (=WORKING= unset or =HOME=). Work-only features are left
out.

Each chapter first explains how a system works day to day, then gives its keys.
[[*Appendix A — Key reference][Appendix A]] collects every custom binding in one place.

The source of truth is always =config/*.org=. When this manual and the config
disagree, the config wins. The module that owns each feature is named in
brackets, e.g. [40-org], so you know where to look.

* Orientation

** Conventions used here
- =C-q= is the *personal prefix*. Press it and wait: which-key lists
  everything under it. =C-q= no longer quotes characters
  (=quoted-insert=); use =M-x quoted-insert= when you need it.
- =C-c <letter>= bindings are the usual user-reserved space. Most org, roam and
  agenda commands live there.
- Keys written as =ññ= or =jj= are *key chords*: two keys pressed together (or
  the same key twice) quickly.
- The Spanish keyboard layout is assumed: =ñ= and =¡¿= appear in bindings.

** What happens at startup
/[init.el, 10-ui, 15-theme, 30-navigation, 80-apps]/
1. The frame opens maximised, with no menu, tool or scroll bars.
2. A dark theme is applied (the first of the dark rotation, see
   [[*Themes, fonts and org styles][Themes]]) and the =hack= font preset is set.
3. The *dashboard* shows the banner, 5 recent files, 5 bookmarks, 5 projects
   and 5 agenda items.
4. The org-roam database starts syncing about a second after you stop typing,
   so that work stays off the startup path.
5. If the encrypted directory (=~/Nextcloud_claro/gocryptfs_claro=) is
   mounted, the journal and Mastodon become available. If not, you get the
   message /Encrypted directory not mounted/ and those two features are
   skipped.

* Everyday editing

** Editing behaviour
/[00-core]/
- *Fill toggle*: =M-q= fills the paragraph (or the region). Press it again
  straight away to unfill it; consecutive presses keep alternating. After any
  other command, the next =M-q= fills again.
- *Kill a word*: =C-w= with no active region kills the word at point.
- *Typing replaces a selection* (=delete-selection-mode=).
- *Paragraph movement*: =M-n= / =M-p= go forward and back by paragraph.
- *Electric pairs*: =(=, ="= and friends close themselves, and so do =¡…!= and
  =¿…?=. =<= is deliberately *not* paired, so tempel's =<= trigger works.
- *Visual undo*: =C-z= opens =vundo=, an undo tree you can walk through.
- *Smarter =C-g=*: it closes a minibuffer even when focus is elsewhere, and
  closes the =*Completions*= window.
- *Diff before saving*: when =C-x s= or =C-x C-c= asks about unsaved buffers,
  answer =d= to see a diff of what would be saved.
- *Abbrevs* are on in text and code buffers, and are saved silently to
  =abbrev_defs= in the data directory.
- Short answers (=y= / =n=) everywhere, and quitting Emacs asks first.
- Files reload automatically when they change on disk. Your place in each file
  is remembered.
- =C-c r r= reloads the whole configuration.

** Spelling and language
/[00-core, 20-completion]/
Spelling is *jinx*, which checks as you type.

| Key   | Command                                |
|-------+----------------------------------------|
| =M-$=   | correct the misspelling at point       |
| =C-M-$= | change this buffer's spelling language |

The default language is *English only*. A Spanish file says so with
=#+language: es= near the top (or a file-local =jinx-languages=). One language
at a time is deliberate: loading both would silently accept every en/es false
friend (/actual/, /once/, /sin/ ...).

In-buffer completion follows the same language: the dictionary words offered
in the completion popup come from that language's hunspell list. So =C-M-$=
switches both the spellchecker and the completion words at once. Words from
your open buffers are offered whatever their language.

** Completion
/[20-completion]/
*Minibuffer*: vertico shows candidates vertically, sorted by prescient (it
learns what you pick). orderless lets you type space-separated fragments in any
order. marginalia adds annotations, with icons.

*In the buffer*: corfu pops up after 3 characters (0.4 s). It offers words from
open buffers plus dictionary words, and closes as soon as you type a space.
=TAB= indents first and completes when there is nothing left to indent.

*Embark*: =C-.= on anything (a candidate, a file name, a URL) opens a menu of
actions for it. =C-h B= lists the current bindings through embark.

*Consult commands*:

* Themes, fonts and org styles

** Themes
/[15-theme]/
There are two rotations:
- dark: =ef-deuteranopia-dark=, =modus-vivendi-tinted=
- light: =leuven=, =ef-deuteranopia-light=, =modus-operandi=

=C-c 0= flips between dark and light. Each flip takes the /next/ theme of that
rotation, so pressing it repeatedly walks through all of them. =C-q t t= picks
any theme by name.

Every theme change also recomputes the current-line colour and the org faces
(below), so the org look stays consistent across themes.

** Font presets
/[15-theme]/
=C-q t f= switches fontaine preset:
| Preset                | Use                                                  |
|-----------------------+------------------------------------------------------|
| =hack=                  | default at startup; Hack everywhere                  |
| =regular=               | Aporetic Sans (prose) + Aporetic Sans Mono (code)    |
| =regular-aporetic-mono= | Aporetic Sans Mono everywhere                        |
| =writing=               | ETBembo 150, extra line spacing                      |
| =writing-big=           | ETBembo 180 (org-scribe's distraction-free mode)     |
| =editing=               | Gentium prose, mono code (org-scribe's editing mode) |

Prose buffers (text and org) use the variable-pitch font. Code blocks, tables,
tags, drawers and comments stay fixed-pitch. =M-+= / =M--= scale the text.

** Org heading styles
/[17-org-style]/
Org headings are drawn from the active theme's own colours in one of three
looks:
| Style | Name              | Headings                                 | Rules                          |
|-------+-------------------+------------------------------------------+--------------------------------|
| =a=     | typographic       | one colour, size and weight only         | none                           |
| =b=     | restrained accent | theme accent on H1/H2, body colour below | none                           |
| =c=     | structured        | one colour                               | hairline over H1/H2 and blocks |

Style =c= is the default.

| Key     | Does                                |
|---------+-------------------------------------|
| =C-q s s= | choose a style                      |
| =C-q s n= | next style (a → b → c)              |
| =C-q s ?= | describe the active style and theme |

Drawers, =#+keywords=, properties and tags are always smaller, fixed-pitch and
dimmed: they are machinery, not content. Heading levels 5–8 fade toward the
background instead of changing colour. The *poet* themes (org-scribe's
writing theme) keep their own heading colour.

** Other visual details
/[10-ui, 17-org-style]/
- Long lines wrap visually everywhere. =C-q t v= toggles visual-fill-column
  (110 characters, centred).
- Line numbers are on everywhere (except in writing focus mode).
- The modeline is doom-modeline, with time and date (and battery on laptops).
- org-modern draws keywords, tags, timestamps, tables and block names more
  cleanly. =#+title= appears as =‣title=.
- org-appear shows hidden emphasis markers, link targets and entities
  (=*bold*=, =\alpha=) when the cursor reaches them, after 0.2 s, and hides them
  again when you leave.

* Org mode

** Defaults worth knowing
/[40-org]/
- Every org buffer is indented (=org-indent-mode=): text sits under its heading
  and only the last star of each heading shows.
- New headings get a blank line before them and go /after/ the current subtree.
- =C-a= / =C-e= on a heading skip the stars, keyword and tags.
- Editing inside a folded region is refused only when it would be blind (=smart=).
- Folded headings end in =…=.
- State-change notes go into a =:LOGBOOK:= drawer. Rescheduling and changing a
  deadline are *not* logged. Finishing a task records a =CLOSED:= timestamp,
  which the weekly review needs.
- Inline images show at startup, up to 800 px wide.
- Babel blocks run without asking for confirmation.

** Tags
/[40-org]/
=C-c C-q= (or =C-c C-c= on a heading) sets tags. Each has a fast-selection key:
| Group     | Tags (key)                                                           |
|-----------+----------------------------------------------------------------------|
| Areas     | personal (=p=), health (=H=), financial (=f=)                              |
| Contexts  | @home (=h=), @errands (=E=), @computer (=c=), @online (=o=), @penpaper (=P=)   |
| Interests | emacs (=e=), writing (=w=), reading (=r=), calls (=C=), blog (=b=), libros (=B=) |
| Energy    | low_energy (=l=), high_energy (=g=)                                      |

The agenda views are built on these tags. An area tag puts a task in the
/Areas of life/ view, and context plus energy tags drive the /Context and energy/
view. Everything in =someday.org= carries =someday= through its =#+FILETAGS=,
which is how the everyday views leave it out.

=libros= sits on the /Libros/ heading of =books.org= and is inherited by every
book. It keeps books out of the /no area/ block of /Areas of life/. =reading= is
for reading that is not a book (articles, sites, courses).

* Agenda and task management

** The files
/[45-agenda]/
The agenda reads =~/Nextcloud/agenda/tasks.org=, =someday.org= and =books.org=.
=tasks.org= is organized as /Inbox/, /Tasks/, /Writing/ and /Calendar/.

The flow the configuration is built for:
1. *Capture* anything into the /Inbox/ with =C-c c t=.
2. *Refile* it (=C-c C-w=) into /Tasks/, /Writing/, a project, =someday.org= or
   =referencias.org=.
3. *Tag* it with an area and, where it helps, a context and an energy level.
4. *Review* it through the views below.

** Look
/[45-agenda]/
- The default span is 14 days starting on Monday.
- A time grid runs from 8:00 to 20:00, with a =⭠ now= marker.
- Categories get SVG icons from =~/Nextcloud/config/icons/= (calendar, tasks,
  projects, financial, birthdays, revision, habits, care).
- DONE items are hidden from scheduled, deadline and timestamp entries.
- Habits (=org-habit=) are enabled: give a task a =STYLE: habit= property and a
  repeater.

** The agenda views
/[46-agenda-personal]/
=C-c a= opens the dispatcher. =C-q d= goes straight to /Daily/.

Each view is designed to answer one question at a set time:
| Key | View               | When                     | Question                                       |
|-----+--------------------+--------------------------+------------------------------------------------|
| =d=   | Daily              | every morning            | what needs my attention today?                 |
| =w=   | Week horizon       | Sunday evening / Monday  | what is coming up this week?                   |
| =R=   | Weekly review      | Friday / weekend         | how did my week go?                            |
| =ca=  | Areas of life      | monthly                  | how are my life areas doing?                   |
| =cw=  | Writing pipeline   | before a writing session | what writing needs attention?                  |
| =cb=  | Libros             | anytime                  | what am I reading, what is next?               |
| =cs=  | Someday and goals  | weekly / monthly         | what is in my someday list?                    |
| =ce=  | Context and energy | a free slot              | what can I do, given where I am and my energy? |

What each view shows, block by block:
- *Daily*: today's agenda (deadlines warn 3 days ahead) · ONGOING · the book
  you are reading (LEYENDO) · priority-A TODOs · WAITING.
- *Week horizon*: deadlines for the next 2 weeks · ONGOING carry-over ·
  priority A · priority B · WAITING.
- *Weekly review*: what was completed in the last 7 days (DONE and FINISHED) ·
  unfinished health · unfinished financial · WAITING /chase or park?/ ·
  unscheduled TODOs /needs a home/.
- *Areas of life*: personal · health · financial · anything with /no/ area tag.
- *Writing pipeline* (=writing= tag): TOWRITE · TOREVIEW · REDO ·
  RESTRUCTURE · the blog queue · the last 10 FINISHED.
- *Libros* (the =books.org= states): LEYENDO · PAUSADO /¿retomar o abandonar?/ ·
  SIGUIENTE · PENDIENTE (alphabetical) · the last 20 LEIDO, newest first by
  =FECHA_FIN=.
- *Someday and goals*: =objetivos= · someday by area · other someday.
- *Context and energy*: high energy + @computer · @home · @penpaper ·
  @errands · @online · calls · low energy /quick wins/.

All views except /Someday/ exclude =someday= items. In the plain agenda
(=C-c a a=), org-super-agenda groups entries into Overdue, Today, Deadline this
week, In progress, Priority A, Waiting, Health, Financial, Personal, Writing,
Lectura (the =libros= tag) and Someday. Entries that match none of these
appear at the end under /Other items/, so nothing scheduled or due is hidden.
The grouping applies to this view only; every other agenda view is plain org.

** The reading list
/[40-org, 46-agenda-personal, 48-books]/
=~/Nextcloud/agenda/books.org= is a plain list of books, in Spanish, with *no
link to org-roam*: book notes live in roam and are made by hand (see
[[*Books][Org-roam → Books]]).

*The life of a book*
1. You want to read it → =C-q l a= (same as =C-c c b=). It asks for the title and
   the author and adds it as =PENDIENTE= with =:FECHA_ALTA:=. You can write why
   you want it, or who recommended it, in the body before =C-c C-c=.
2. You pick it as one of the next → =C-c C-t s= (=SIGUIENTE=). Keep three or
   fewer.
3. You start it → =C-c C-t l= (=LEYENDO=). =:FECHA_INICIO:= is stamped the first
   time only, so pausing (=z=, which asks why) and resuming keeps it.
4. You finish it → =C-c C-t t= (=LEIDO=). =:FECHA_FIN:= is stamped and it asks
   for a rating (1–5, =:VALORACION:=) and a one-line comment (=:COMENTARIO:=,
   skipped if empty).
5. Or you give up → =C-c C-t a= (=ABANDONADO=). It asks why and stamps
   =:FECHA_FIN:=.

Finished books stay in the list as =LEIDO=. Archive them (=C-c C-x C-a=) once a
year if the file gets long. Nothing else is asked for: add any other property
by hand with =C-c C-x p=. The dates are stamped by a hook that only acts in
=books.org=, and it works from the agenda too.

*Seeing the list*
- =C-q l v= (=C-c a cb=): the /Libros/ view, described above.
- The /Vistas/ heading at the top of =books.org= holds two tables: /Por leer/
  (SIGUIENTE and PENDIENTE) and /Leídos/ (with rating and comment). Refresh them
  with =C-u C-c C-x C-u=. They list books in file order, so sort the list by
  state first with =C-c ^ o= on /Libros/.
- =C-c C-x C-c= on /Libros/ opens an editable column view. =S-left= / =S-right=
  cycles the rating.
- =C-q l f= opens =books.org= and jumps to a book by name.

| Key     | Does                                        |
|---------+---------------------------------------------|
| =C-q l a= | add a book                                  |
| =C-q l v= | the /Libros/ view                             |
| =C-q l f= | find a book in =books.org=                    |
| =C-q l d= | =:read:= entries in the dailies               |
| =C-q l m= | move the idea at point into a note (refile) |

* Org-roam — the knowledge base
Org-roam holds ideas meant to be *reused*: concepts, claims about how people,
history or the craft work, and notes on what you read. It serves both writing
(characters, emotions, plot, the Siglo de Oro, magic) and general thinking
(philosophy, psychology, productivity) in one graph. A good note still makes
sense years later, out of context, and can be linked from any story or essay.

The system rests on three ideas:
- *Capture is cheap, a note is earned.* A thought goes into the inbox in two
  seconds. It only becomes a note when you process it.
- *The system keeps its own bookkeeping.* The =roamtag=, =seed= and =daily= tags
  are added and removed by hooks. You never set them by hand.
- *Each place has one job.* Roam, =retazos/=, the journal, the agenda and the
  dailies each hold a different kind of thing.

The reasoning behind this workflow, and the state of the store when it was
designed, are in =~/Nextcloud/orgroam-system.org=.

*Roam or retazos?* Ask: /would this still be useful if that story were never
written?/ Yes → roam. No → retazos. A retazos idea can cite the roam notes it
draws on (=C-c n i= works in any org file). The story then shows up in each
note's backlinks, so a concept note tells you which stories use it.

** Kinds of note
A convention for titles and shape, not something the config enforces.
| Kind    | Title                        | Example                          | Shape                                                   |
|---------+------------------------------+----------------------------------+---------------------------------------------------------|
| Concept | a noun or short phrase       | /miedo/, /cábala/, /Imperio Español/   | a definition in your words, and links out               |
| Claim   | a full sentence that asserts | /la trama no es la historia/       | one idea, argued in a few paragraphs                    |
| Source  | title – author (– type)      | /2k to 10k – Rachel Aaron – libro/ | the source, then a list of links to claim notes         |
| Hub     | the topic                    | /personajes/, /estoicismo/           | an annotated list of links, tended in the weekly review |

- *Prefer claims.* A claim is what you actually cite when writing. When a
  concept note grows long, split the claims out of it.
- *Link out before you leave.* Every new note gets at least one link: to a
  concept, a hub, or the source it came from.
- *Sources point to ideas, they don't hold them.* Write each idea as a claim
  note, and list it under the book's /Notas/ with a line of context.
- *Write in the language of the source.* When you will search for a note in
  the other language, add an alias (=M-x org-roam-alias-add=).

** Capturing
/[40-org, 50-org-roam]/
Three ways in, from lightest to heaviest:
- *A thought*: =C-c n n= adds a timestamped entry to the inbox. One line is
  enough, and you don't have to decide where it goes yet. It is the same as
  =C-c c f=.
- *Something you read*: =C-c n d r= asks what it was and adds a =:read:= entry to
  today's daily. Link the source note if it has one, and add a line of
  reaction. Keep it to a log line. If you find yourself arguing a point, that
  belongs in a claim note: write the note and link it from the daily.
  An idea about a *book* you are reading is the exception: it doesn't stay in
  the daily, because the daily pass moves it into the book's note (see [[*Books][Books]]).
- *A new idea while writing a note*: =C-c n i=, type the new title, and choose
  template =s= (seed). The link goes in and you stay where you are. The new note
  is an empty placeholder tagged =seed=.

** The daily pass — five minutes
Open the inbox (=C-c n F=) and handle each entry in one of four ways:
1. *Delete it*: it has served its purpose, or wasn't worth keeping.
2. *Append it* to an existing note (=C-c n f=), adding a link if it connects two
   notes.
3. *Make a note of it*: =C-c n f=, type a new title (a sentence, for a claim),
   template =p=, then link it out once.
4. *Send it elsewhere*: a story seed to =C-c c w=, a task to =C-c c t=.

Then move the book ideas out: =C-q l d= lists the =:read:= entries in the
dailies, and =C-q l m= on each book idea moves it into its book's note (see
[[*Books][Books]]). Leave the other reading-log entries where they are.

Delete the entry once it is handled. The goal is an empty inbox; if you skip a
day, the weekly review catches up.

** The weekly review — twenty to thirty minutes
In this order, stopping when time runs out:
1. *Empty the inbox*, if the daily pass slipped.
2. *Read the week's dailies* (=C-c n d b= / =f= step between them). Promote
   anything worth keeping into claim notes, and link them from their source
   notes.
3. *Develop two seeds* (=C-c n S=). Write a few lines. If a seed no longer means
   anything, delete the file; the links pointing to it then show as broken, so
   remove them and run =M-x org-roam-db-sync=.
4. *Connect one orphan* (=M-x my/org-roam-orphans=): link it to a hub or a
   concept.
5. *Try one creative pair* (=C-c n P=). If the two notes do connect, write the
   claim that connects them. If not, skip it.
6. *Tend a hub*: if a topic gained several notes this week, add them to its hub
   with a line of context each.

Dailies are never processed away: they are the record of what you took in.
The one exception is book ideas, which the daily pass moves into the book's
note.

** Using it when writing
- Start from a hub or a concept (=C-c n f= /personajes/, /miedo/, /trama/ ...) and
  follow its backlinks (=C-c n l=).
- The node picker matches tags as well as titles: type =writing= or =emoción=
  after part of a title to narrow the list.
- In retazos and scene files, =C-c n i= cites a roam note. The story then
  appears in that note's backlinks.

** Books
/[48-books, 50-org-roam]/
The reading list (=books.org=, see [[*The reading list][The reading list]]) and the book notes are kept
*separate on purpose*: the list tracks states and dates, and the roam note is
the book's *master note*, where everything you think about it ends up. Nothing
links the two, so a book can be on the list without a note, and vice versa.

1. *You want notes on a book* → =C-c n f=, type the title, and choose template
   =b=. It asks for the author and the year.
2. *While reading* → =C-c n d r= in the moment. The idea goes into today's daily,
   tagged =:read:=.
3. *At the daily pass* → =C-q l d= lists the =:read:= entries in the dailies.
   On each book idea, =C-q l m= (=org-roam-refile=) and pick the book's note:
   the entry is *moved* there, appended as a heading at the end, and removed
   from the daily. =C-q l m= only offers notes that exist, so create the note
   first (step 1).
4. *In the note* → file the idea under /Temas/, /Conceptos/ or /Frases/, turn
   mentions of other notes into links (=C-c n i=), and grow the best ideas into
   claim notes listed under /Notas/.

No book idea should survive the daily pass. =C-q l d= also lists the ordinary
reading-log entries (they carry the same =:read:= tag), and those stay.

** Tags
/[50-org-roam]/
Three tags look after themselves:
- =roamtag=: the note has a live TODO (not DONE). It is checked when a note is
  opened or saved. =C-c n T= picks a random note from these, and =C-c n a= shows
  their TODOs. At home, roam TODOs are deliberately *not* merged into the main
  agenda.
- =seed=: the note has nothing beyond its title. It is added on save while the
  note is empty and removed on the first save with a body. Dailies never get
  it. =C-c n S= opens a random seed; =C-c n f= and typing =seed= lists them.
- =daily=: set by the dailies template.

Other tags are for *filtering*; links do the connecting. Keep them few, and use
one tag per idea in one language: =writing= (not =escritura=), =personaje= (not
=character=), =productividad= (not =productivity=). =personaje= is a fiction
character; a real, historical person is =person=. Notes about note-taking itself
(second brain, org-roam, writing to think) are =pkm=. The main ones are =writing=,
=filosofía=, =psicología=, =historia=, =productividad=, =magic=, =emacs=, plus
narrower ones such as =personaje=, =trama=, =worldbuilding=, =emoción=,
=estoicismo= and =siglodeoro=. =book= is set by the book template.

** org-scribe in this configuration

org-scribe is your writing toolkit. It is loaded from
=~/Nextcloud/escritura/software/org-scribe= if that directory exists, otherwise

| Mode                     | Theme                | Font preset | Width |
|--------------------------+----------------------+-------------+-------|

| distraction-free / focus | =poet=                 | =writing-big= |    75 |
| editing                  | =leuven=               | =editing=     |    90 |

- *Search*: =1= by PoV, =2= character, =3= plot, =4= location, =5= TODOs, =6= edit

* Export and publishing

** Exporting
/[55-org-export]/
=C-c C-e= opens the export dispatcher. Available backends: HTML, Markdown,
Org, LaTeX/PDF, Beamer, EPUB, Pandoc (every format pandoc supports) and Hugo.

- A heading tagged =:ignore:= is dropped from the export but *its content is
  kept*. This is how chapter and scene headings disappear from a manuscript.
- A heading tagged =:noexport:= is dropped with its content.
- Smart quotes are on, HTML exports have no "validate" link, and code in LaTeX
  uses =minted=.
- The =<export= tempel template inserts a complete settings heading.

** LaTeX classes

|----------------------+-----------------------------------------------------------------|

| =memoir_draft=         | the same, draft mode                                            |
| =memoir_chapter=       | chapters as the top level (no parts), final                     |
| =memoir_chapter_draft= | chapters as the top level, draft                                |
| =reporting=            | memoir with plain page style, Spanish                           |
| =ews=                  | the Emacs Writing Studio book layout (EB Garamond, 9.25×7.5 in) |

The Spanish classes define three commands you can use in =#+LATEX:= lines or
export snippets: =\fin= (a scene break), =\edit{…}= (an inline todo note) and

the temporary files are cleaned afterwards.

* Where state lives
Nothing personal is committed to this repo. State lives in the *data
directory*, =~/Nextcloud/config/.emacs.d/=, and syncs between machines:
- =backups/=: numbered backups of every file you save (6 new, 2 old kept)
- =recentf=, =savehist= (including the kill ring, searches and the last writing
  project), =bookmarks=, =org-id-locations=
- =abbrev_defs=, =prescient-save=, =projects=, =nov-places=
- =elfeed/= (database and =elfeed.org=), =perspectives/=
- =cape-dict-*= (plain word lists, generated once from hunspell)
- =personal_info.el= (your name and email; loaded at startup)

The encrypted directory holds the journal and the Mastodon token.
