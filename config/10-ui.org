Everything about how the frame looks: sizing, fringes, cursor, the current-line
highlight, line numbers, wrapping, icons, the modeline and the centred writing
view.

The =hl-line= colours live here rather than with the themes: one set of colours
and one =my/set-hl-line-face=, applied whenever a theme is enabled.

(defun my/org-tree-open-in-right-frame ()
  "Open the current Org subtree in an indirect buffer in the right window.
If there is only one window, create a right-side window first.
Then, always move focus to that right window."
  (interactive)
  (let ((right-win (window-right (selected-window))))
    ;; If there's no window to the right, create one
    (unless right-win
      (setq right-win (split-window-right)))
    ;; Show the subtree in an indirect buffer
    (org-tree-to-indirect-buffer)
    ;; Move to the right window
    (select-window right-win)))

* Line numbers
This determines the style of line numbers in effect. If set to `nil', line numbers are disabled. For relative line numbers, set this to `relative'.

Line numbers are on in programming and configuration (=conf-mode=) buffers
only.  In text buffers (org,
markdown) they are off: Emacs draws them inside the text area, so they would
take about 4 of the =my-prose-width= columns that visual-fill-column sets
aside for prose.
#+begin_src emacs-lisp
  ;; Calculate width based on total lines in buffer at start
  (setq display-line-numbers-width-start t)
  (setq display-line-numbers-offset 0)
  (setq display-line-numbers-type t)
  (setq display-line-numbers-grow-only t)
  (add-hook 'prog-mode-hook #'display-line-numbers-mode)
  ;; conf-mode (.ini, .toml, .gitconfig, /etc files) derives from neither
  ;; prog-mode nor text-mode, so it needs its own hook.
  (add-hook 'conf-mode-hook #'display-line-numbers-mode)
#+end_src

* Fill column mode
We want to use the visual fill column mode to limit the width of the lines, even if they don't reach the right edge.

When reaching the established width defined, the line will wrap, even before getting into the right border of the application.

It turns on by itself in every =text-mode= buffer, which includes the modes
derived from it (org, markdown, git commit messages).  =:hook= defers the
package until the first such buffer; =:config= still runs before the mode
does, because loading the file is what the autoload triggers first.

=writeroom-mode= saves and restores this mode itself.  =my/centered-mode=
sets the same window margins, so it pauses this mode while it is on.

=my-prose-width= is the one place the line width is set.  At home it is 72,
chosen for comfort when writing fiction: studies and typographic practice put
the comfortable line at about 66 characters, and =org-indent-mode= takes 2
columns per heading level, so 72 leaves 66 for scene text under a level-3
heading.  Work keeps 100, for notes and agendas rather than prose.  The
reasoning is in the design note =20261125-line-width.org=.  org-scribe's own
widths are its business and are set in =60-writing=.

*Proportional fonts.*  The width is counted in the font's /nominal/ character
width, which for a proportional font is wider than its average letter.  At 72,
ETBembo (=writing=) fit about 81 characters per line where Hack fits 63.
So the presets with a proportional prose font get their own width, chosen so
that their lines match Hack's at 72 (measured on Spanish prose under a level-3
heading).  Any other preset, and every work preset, uses =my-prose-width=.  The
width follows the preset through =fontaine-set-preset-hook=.  The measurements
are in the design note =20261125-prose-visuals.org=.
#+begin_src emacs-lisp
  (defvar my-prose-width (if my-workenvironment-p 100 72)
    "Line width, in columns, for prose and text buffers.
Used by `visual-fill-column-width' (unless the fontaine preset is in
`my-prose-width-by-preset') and `my/centered-content-width'.")

  (defvar my-prose-width-by-preset
    '((writing     . 57)            ; ETBembo
      (writing-big . 57)            ; ETBembo, larger: same count
      (editing     . 65)            ; Gentium
      (reading     . 60))           ; Literata
    "Prose width for fontaine presets whose prose font is proportional.
Each value gives the same characters per line as `my-prose-width' does
in Hack.  Presets not listed use `my-prose-width'.")

  (defun my/prose-width ()
    "The prose width for the current fontaine preset."
    (alist-get (bound-and-true-p fontaine-current-preset)
               my-prose-width-by-preset my-prose-width))

  (defun my/prose-width-follow-preset ()
    "Set the default prose width for the new preset and refit every window.
Buffers with their own `visual-fill-column-width' (writeroom, org-scribe)
keep it.  Runs from `fontaine-set-preset-hook'."
    (when (featurep 'visual-fill-column)
      (setq-default visual-fill-column-width (my/prose-width))
      (dolist (window (window-list-1 nil 'nomini t))
        (with-selected-window window
          (visual-fill-column-adjust)))))

  (add-hook 'fontaine-set-preset-hook #'my/prose-width-follow-preset)

  ;; visual fill column mode
  (use-package visual-fill-column
    :ensure t
    :hook (text-mode . visual-fill-column-mode)
    :config
    ;; This sets the value to all the buffers, as initially it is a per-buffer variable.
    (setq-default visual-fill-column-width (my/prose-width))
    ;; Keep the text at the left edge: the margin goes on the right only.
    ;; `visual-fill-column-toggle-center-text' centres a single buffer.
    (setq-default visual-fill-column-center-text nil))
#+end_src

* Prose line spacing
Prose buffers get more space between lines than code: =my-prose-line-spacing=
is set buffer-locally in every =text-mode= buffer (and in epubs, from
=80-apps=), and it overrides the fontaine presets' =:line-spacing= there.  The
presets still decide the spacing of code and everything else.

It is a float, a fraction of the frame's line height: 0.3 brings prose to
about 1.5 times the font size, which is where the accessibility guidelines
put comfortable reading.  An integer would be pixels, which is what the
presets use (0 or 1).  The reasoning is in the design note
=20261125-prose-visuals.org=.
#+begin_src emacs-lisp
  (defvar my-prose-line-spacing 0.3
    "Line spacing for prose buffers: a fraction of the frame's line height.")

  (defun my/prose-line-spacing ()
    "Give the current buffer `my-prose-line-spacing'."
    (setq-local line-spacing my-prose-line-spacing))

  (add-hook 'text-mode-hook #'my/prose-line-spacing)
#+end_src

* Highlighting the line when changing windows
Using built-in =pulse.el= instead of the external =pulsar= package.

The default =pulse-highlight-start-face= is mustard on dark themes and nearly
white on clear ones, and every theme re-themes it, so it gets clobbered on each
=consult-theme=.  Instead we define our own face and pass it explicitly to
=pulse-momentary-highlight-one-line=: no theme touches it, so no re-application
hook is needed when switching between dark and clear themes.

The colour is picked for a relative luminance of ~0.18, where the contrast
against a near-white and a near-black background is balanced (~4.6:1 both ways).
It also stays distinct from the neutral grey of =hl-line=.  Alternatives with the
same property: violet =#7f5fbf=, steel blue =#4a7fa5=.
#+begin_src emacs-lisp
  (require 'pulse)

  (defface my-pulse-line-face
    '((t :background "#26837e" :extend t))
    "Face for `my/pulse-line', readable on both dark and clear themes.")

  ;; nil in Emacs 32 by default, which means a static highlight instead of a fade
  (setq pulse-flag t)
  (setq pulse-iterations 20)
  (setq pulse-delay 0.10)

  (defun my/pulse-line (&rest _)
    "Briefly highlight the current line using built-in pulse.el."
    (interactive)
    (pulse-momentary-highlight-one-line (point) 'my-pulse-line-face))

  ;; Pulse after navigation commands
  (dolist (cmd '(scroll-up-command scroll-down-command
                 recenter-top-bottom other-window
                 windmove-left windmove-right windmove-up windmove-down))
    (advice-add cmd :after #'my/pulse-line))

  ;; Pulse after consult jumps
  (add-hook 'consult-after-jump-hook #'my/pulse-line)

  (global-set-key (kbd "C-x l") #'my/pulse-line)
#+end_src

* Center a buffer in screen
Sometimes I have just a single window and this is a problem for me in a big screen. This code just centers the text in the middle.
Useful for reading books or long texts.

#+begin_src emacs-lisp
  (defcustom my/centered-content-width my-prose-width
    "Width of the centered content area in characters."
    :type 'integer
    :group 'editing-basics)

  (defun my/centered-content-width-value ()
    "Prompt the user for a value and set `my/centered-content-width` to it."
    (interactive)
    (setq my/centered-content-width (string-to-number (read-from-minibuffer "Value for centered width: "))))

  (defvar my/centered-mode nil)

  (defvar-local my/centered--paused-visual-fill-column nil
    "Non-nil if `my/centered-mode' turned off `visual-fill-column-mode'.
Both modes set the window margins, so only one may be on at a time;
turning `my/centered-mode' off turns the other one back on.")

  (define-minor-mode my/centered-mode
    "Minor mode to center buffer content using margins and visual line mode."
    :init-value nil
    :global nil
    :lighter " [Centered]"
    :group 'editing-basics
    (if my/centered-mode
        (progn
          (when (bound-and-true-p visual-fill-column-mode)
            (setq my/centered--paused-visual-fill-column t)
            (visual-fill-column-mode -1))
          (visual-line-mode 1)
          (add-hook 'window-configuration-change-hook
                    #'my/centered--update-margins nil t)
          (dolist (w (get-buffer-window-list nil nil t))
            (my/centered--update-margins w)))
      (progn
        (visual-line-mode 1)
        (remove-hook 'window-configuration-change-hook
                     #'my/centered--update-margins t)
        ;; every window showing the buffer, not just the selected one
        (dolist (w (get-buffer-window-list nil nil t))
          (set-window-margins w 0 0))
        (when my/centered--paused-visual-fill-column
          (setq my/centered--paused-visual-fill-column nil)
          (visual-fill-column-mode 1)))))

  (defun my/centered--update-margins (&optional window)
    "Centre `my/centered-content-width' columns of text in WINDOW.
WINDOW defaults to the selected one, which is the window being updated
when this runs from the buffer-local `window-configuration-change-hook'.
The margins are sized from the window's own text area (its body width plus
the margins it already has), not the frame's width, so a split frame
centres each window on its own."
    (let* ((window (or window (selected-window)))
           (margins (window-margins window))
           (width (+ (window-body-width window)
                     (or (car margins) 0) (or (cdr margins) 0)))
           (margin (max 0 (/ (- width my/centered-content-width) 2))))
      (set-window-margins window margin margin)))
#+end_src

* Current-line highlight colours
One set of colours and one function.  The work environment sets the
foreground explicitly while the personal themes look better letting the theme
choose it, so that difference is an argument rather than a second copy.

It is applied from =enable-theme-functions=, so every way of enabling a theme
(=C-c 0=, =C-q t t=, org-scribe's mode switches, a plain =load-theme=) gets the
right colours.  Whether the theme is dark is read from the =default= background
it just installed, rather than tracked in a variable.  The hook is registered
here, before =15-theme= loads the startup theme.

Two themes are skipped: =user= (Customize's own settings) and =fontaine= (fonts
only).  Neither changes the palette.

#+begin_src emacs-lisp
  (defvar my-hl-line-dark-background "#303030"
    "Background color for `hl-line' when a dark theme is active.")
  (defvar my-hl-line-dark-foreground "#f0f0f0"
    "Foreground color for `hl-line' when a dark theme is active.")
  (defvar my-hl-line-clear-background "#e0e0e0"
    "Background color for `hl-line' when a clear theme is active.")
  (defvar my-hl-line-clear-foreground "#202020"
    "Foreground color for `hl-line' when a clear theme is active.")

  (defun my/set-hl-line-face (dark-p &optional with-foreground)
    "Set the `hl-line' face colors for a dark or clear theme, based on DARK-P.
The foreground is only touched when WITH-FOREGROUND is non-nil, so that
the personal themes keep whatever foreground the theme itself picked."
    (set-face-attribute 'hl-line nil
                        :background (if dark-p
                                        my-hl-line-dark-background
                                      my-hl-line-clear-background))
    (when with-foreground
      (set-face-attribute 'hl-line nil
                          :foreground (if dark-p
                                          my-hl-line-dark-foreground
                                        my-hl-line-clear-foreground))))

  (defun my/theme-dark-p ()
    "Non-nil when the active theme has a dark background.
Falls back to the frame's `background-mode' when the background cannot be
read, as on a TTY or in batch."
    (require 'color)
    (let ((rgb (color-name-to-rgb (face-background 'default nil t))))
      (if rgb
          (color-dark-p rgb)
        (eq (frame-parameter nil 'background-mode) 'dark))))

  (defun my/theme-palette-p (theme)
    "Non-nil when enabling THEME can change the palette.
`user' and `fontaine' hold customizations and fonts, not colours."
    (not (memq theme '(user fontaine))))

  (defun my/hl-line-after-theme (theme)
    "Recolour `hl-line' for THEME.  Runs from `enable-theme-functions'.
Work sets the foreground as well; the personal themes keep their own."
    (when (my/theme-palette-p theme)
      (my/set-hl-line-face (my/theme-dark-p) my-workenvironment-p)))

  (add-hook 'enable-theme-functions #'my/hl-line-after-theme)
#+end_src
