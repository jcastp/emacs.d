* Personal keymap infrastructure
=C-q= is my own prefix map.  It used to be built in one place at the end of the
config, which meant that file had to know the names of personal-only and
work-only commands and guard each one with =fboundp= / =boundp=.  Those guards
failed silently: a renamed command left a dead key with no warning.

Now the map is created here, empty, and each module registers its own entries
with the two helpers below.  A module that does not load contributes nothing —
the condition is the module's own, not a guess made from a symbol's name.

Binding =C-q= this early also makes it a prefix key before any package tries to
bind beneath it.  =org-jira= binds =C-q j b= and used to fail with "starts with
non-prefix key C-q", because the map was only installed at the very end.

From https://protesilaos.com/codelog/2024-01-29-emacs-prefix-map/

#+begin_src emacs-lisp
  (defvar my/key-prefix-map (make-sparse-keymap)
    "My personal keymap, bound to `C-q'.
Modules register their own entries with `my/key-define' and
`my/key-define-submap'.")

  (keymap-set global-map "C-q" my/key-prefix-map)

  (defun my/key-define (key name def &optional map)
    "Bind KEY to DEF, labelled NAME, in MAP.
MAP defaults to `my/key-prefix-map'.  NAME is what which-key and
`describe-keymap' show for the binding."
    (keymap-set (or map my/key-prefix-map) key (cons name def)))

  (defun my/key-define-submap (key name &optional map)
    "Register a fresh sub-keymap under KEY, labelled NAME, and return it.
MAP defaults to `my/key-prefix-map'.  The caller fills the returned
keymap in with `my/key-define'."
    (let ((sub (make-sparse-keymap)))
      (keymap-set (or map my/key-prefix-map) key (cons name sub))
      sub))
#+end_src

** How to add a binding
The rule is: *the binding lives in the module that owns the command*, in that
module's own "Keymap entries" section at the end of the file — never here.  If
the module does not load, the key simply is not there, and nothing has to test
for it.

The examples below are illustrative only (=:tangle no=), they are not part of
the running config.

A plain binding on =C-q=.  =NAME= is the label which-key and =C-h k= show:
#+begin_src emacs-lisp :tangle no
  ;; C-q c → my/centered-mode, shown as "centered mode"  (10-ui.org)
  (my/key-define "c" "centered mode" #'my/centered-mode)
#+end_src

A sub-map, so several related commands share one letter.  =my/key-define-submap=
returns the new keymap; pass it as the fourth argument of =my/key-define=:
#+begin_src emacs-lisp :tangle no
  ;; C-q t f, C-q t t, C-q t v  (15-theme.org)
  (let ((themes (my/key-define-submap "t" "themes and fonts")))
    (my/key-define "f" "font preset" #'fontaine-set-preset themes)
    (my/key-define "t" "theme"       #'consult-theme       themes))
#+end_src

An entry that only makes sense in one environment or on one machine: wrap it in
the same predicate the rest of the feature uses.  No =fboundp= guard — if the
predicate holds, the command is there:
#+begin_src emacs-lisp :tangle no
  (when my-workenvironment-p
    (my/key-define "p" "open report" #'my/open-report))
#+end_src

If a sub-map has to be built earlier than where it is registered (because a
=use-package= form fills it in), define it as a variable and hand that variable
to =my/key-define=, which accepts a keymap as =DEF= just as well as a command:
#+begin_src emacs-lisp :tangle no
  (defvar my/key-prefix-writing-map (make-sparse-keymap) "Writing commands.")
  ;; … use-package forms add entries to it …
  (my/key-define "w" "writing" my/key-prefix-writing-map)   ; 60-writing.org
#+end_src

Free letters are worth checking against the table in =CLAUDE.md= (or just press
=C-q= and read which-key) before claiming one.

* Alternative and better C-g function
https://emacsredux.com/blog/2025/06/01/let-s-make-keyboard-quit-smarter/

#+begin_src emacs-lisp
  (defun er-keyboard-quit-dwim ()
    "Do-What-I-Mean behaviour for a general `keyboard-quit'.

  The generic `keyboard-quit' does not do the expected thing when
  the minibuffer is open.  Whereas we want it to close the
  minibuffer, even without explicitly focusing it.

  The DWIM behaviour of this command is as follows:

  - When the region is active, disable it.
  - When a minibuffer is open, but not focused, close the minibuffer.
  - When the Completions buffer is selected, close it.
  - In every other case use the regular `keyboard-quit'."
    (interactive)
    (cond
     ((region-active-p)
      (keyboard-quit))
     ((derived-mode-p 'completion-list-mode)
      (delete-completion-window))
     ((> (minibuffer-depth) 0)
      (abort-recursive-edit))
     (t
      (keyboard-quit))))

  (global-set-key [remap keyboard-quit] #'er-keyboard-quit-dwim)
#+end_src

  (defun my/reload-config()
    "Reloads my emacs configuration."
    (interactive)
    (let ((my-init-file (expand-file-name "init.el" user-emacs-directory)))
      (message "This: %s" my-init-file)
      (if (file-exists-p my-init-file)
  	;; if

  	  (load my-init-file)

** jinx
We define the english language as the default one.

To apply another dictionary to a particular file, add a local variable or an org property =#+language: es= to the file.

#+begin_src emacs-lisp
  (use-package jinx
  :ensure t
  :demand t
  :hook (emacs-startup . global-jinx-mode)
  :bind (("M-$" . jinx-correct)
         ("C-M-$" . jinx-languages))
  :init
  ;; One language at a time.  A buffer that needs the other one says
  ;; so explicitly: `#+language: es' in org, a file-local
  ;; `jinx-languages', or C-M-$ interactively.  Loading both
  ;; dictionaries at once makes `jinx--word-valid-p' accept the
  ;; union, which silently passes every en/es false friend
  ;; (actual, once, red, sin, pie, solo).
  (setq jinx-languages "en"))
#+end_src

* Persistent state files
The home and work instances must not overwrite each other's history, so the
state files are suffixed per environment.  Previously =recentf= and =savehist=
were configured in the personal config and re-implemented in the work config,
which meant work silently ran with =recentf-max-saved-items= at its default of
25, no =recentf-exclude= list, and no bookmark file of its own — bookmarks were
landing in the committed =~/.emacs.d/bookmarks.eld=.  One definition, one
suffix, both environments.

#+begin_src emacs-lisp
  (defvar my-state-file-suffix (if my-workenvironment-p "-work" "")
    "Suffix distinguishing the work instance's state files from the personal ones.")

  (defun my/state-file (name)
    "Return the path of state file NAME in `my-data-dir'.
  The name is suffixed with `my-state-file-suffix' so that the home and
  work instances keep separate history."
    (expand-file-name (concat name my-state-file-suffix) my-data-dir))
#+end_src

** Save command history
It is nice to have commands and their history saved so that every time you get
back to work, you can just re-run stuff as you need it.

The last entry of =savehist-additional-variables= is the one genuinely
environment-specific part: the writing project at home, the direct report at
work.
#+begin_src emacs-lisp
  (setq savehist-file (my/state-file "savehist"))
  (setq history-length t
        history-delete-duplicates t
        savehist-save-minibuffer-history t)
  (setq savehist-additional-variables
        (append '(kill-ring
                  search-ring
                  regexp-search-ring)
                (if my-workenvironment-p
                    ;; remember the last direct report across sessions
                    '(my/last-report)
                  ;; remember the last writing project across sessions
                  '(my/last-writing-project))))
  (savehist-mode 1)
#+end_src
